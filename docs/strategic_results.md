# 停滯時加入碰撞小球：實作與 smoke experiment

本輪完成了停滯偵測、有限供能發球器、真實飛行接觸，以及兩種直接速度擾動對照。**物理機制與記帳可以正常運作，但這組固定設定沒有顯示小球優勢。** 壞谷逃脫為小球 0/20、隨機擾動 7/20；接近好解時，三種介入都可能阻礙後續收斂。

結果來自二維合成地形，另加一個高度座標。這是既有純重力群體原型上的策略實驗，沒有另加水平梯度力，尚未接到 momentum SGD、AdamW 或 NanoGPT。

## 完整流程

1. 從一個目標粒子開始，按原本的重力、阻尼與接觸規則運動。
2. 每隔物理時間 1，檢查上一個視窗的三個條件：相對最佳 loss 進展 ≤ `1e-4`、平均水平動能 ≤ `0.002`、正規化路徑活動 ≤ `0.05`。
3. 連續兩個視窗都成立，才允許介入。成功介入後冷卻 4；最多兩次，單次供能 0.20，總上限 0.40。
4. 發球組檢查目標是否離地，抽取水平發球方向，規劃約 0.025 後接觸的初態。規劃明確包含緊接的共同阻尼；兩球初始不重疊。
5. 檢查短期內沒有更早的地形碰撞或其他粒子碰撞。不可行則放棄該規劃，查詢照常計費；每次最多 8 個方向，整條軌跡最多 20 次規劃機會。
6. 提交新增小球事件並記入外部能量、動量，再由原排程器推進到真實接觸，依接觸法線計算彈性衝量。輔助球保留在系統內。
7. 只用原目標粒子的 loss、越障與目標命中評分，繼續記錄能量轉移、做功、耗散與成本。

停滯觸發的是「發球」，碰撞反射仍是實際接觸的結果。判準也沒有能力分辨「壞的局部極小值」與「接近好解」；後者正是本輪控制案例要檢查的問題。已知極小值只用於建立初態與事後評分，沒有提供給停滯判準或方向選擇。

## 比較設計

| 組別 | 介入 | 額外幾何規劃 |
|---|---|---|
| 繼續運動 | 無 | 無 |
| 隨機擾動 | 直接增加目標水平動能 0.20 | 無 |
| 方向配對擾動 | 沿可行發球對應的方向，直接增加目標水平動能 0.20 | 與發球組相同的規劃 |
| 輔助小球 | 新增總機械能 0.20 的球，等待真實碰撞 | 有 |

三種介入使用相同偵測器與供能上限。後續軌跡不同，觸發時間與實際花費可以不同。方向配對組與小球組共 60 組首次成功介入，其時間與方向差異均為 0；不宣稱後續介入也逐次配對。

固定參數為 `g=0.5`、`h=0.05`、`beta=0.995`、接觸距離 `rho=0.12`，觀察至時間 25。三種案例、各 20 個種子、四組策略，共 240 條軌跡。每個種子的四組共用相同目標初態。

所有軌跡有共用於整個群體的 12,000 次 oracle 呼叫上限；值、梯度與解析路徑每次各計一個呼叫，種類另列。這是記帳單位，不代表三種操作等耗時。另以事先固定的 `3*steps=1,500` 次上限比較，只選上限內最後一筆已提交紀錄，不插值或外推。粒子對預測另行記錄。

壞谷位於傾斜雙井較差的右井。所有種子的初始機械能都低於障壁能量約 0.125626，因此沒有外部供能時確實無法越障。好谷位於較低的左井附近；第三例為二次函數附近。

## 優化結果

「命中」要求在保存的觀察點把初始 loss 差距降低至少 90%；雙井另需處於較低的左井。表中的次數是在時間 25 前曾命中，並不表示最終仍停在好解。

| 案例 | 繼續運動 | 隨機擾動 | 方向配對擾動 | 小球 |
|---|---:|---:|---:|---:|
| 壞谷：越障且命中 | 0/20 | 7/20 | 2/20 | 0/20 |
| 好谷附近：命中 | 20/20 | 9/20 | 9/20 | 9/20 |
| 二次函數附近：命中 | 20/20 | 20/20 | 20/20 | 20/20 |

1,500 次呼叫上限下，三列命中次數相同，240 條軌跡都涵蓋該上限，沒有缺失樣本。這不代表兩種預算的其他指標完全相同。

最佳 loss 的正規化差距為 `(best_f-f_min)/(initial_f-f_min)`，越小越好。下表為時間 25 的中位數；好谷的初始絕對差距很小，因此同時保留絕對指標。

| 案例 | 繼續運動 | 隨機擾動 | 方向配對擾動 | 小球 |
|---|---:|---:|---:|---:|
| 壞谷 | 0.999060 | 0.998328 | 0.999122 | 0.999171 |
| 好谷附近 | 0.001810 | 0.311402 | 0.293817 | 0.159853 |
| 二次函數附近 | 0.000240 | 0.002257 | 0.002257 | 0.001276 |

壞谷的中位數會掩蓋少數逃脫，因此必須與命中次數一起看。相較繼續運動，小球在壞谷為 0 個改善、19 個惡化、1 個平手；其中惡化大多只是局部谷底附近的小差異。好谷也是 0/19/1，二次函數為 1/19/0，不能只挑那個改善案例作結論。

在好谷，最佳 loss 的絕對差距中位數由繼續運動的 `2.18e-7` 變成小球的 `1.35e-5`。最終當前位置的差距分別為 `3.09e-6` 與 `9.77e-3`，顯示保存歷史最佳解會遮住部分擾動代價。完整的當前／最佳指標見 `terminal_scores.csv`。

## 碰撞、供能與做功

發球不是封閉系統。固定重力位能零點 `z=0`，全系統能量為 `H=sum(K+g*z)`；新增球帶入的完整機械能、動量是明確的來源項。單次插入 0.20 不等於目標得到 0.20 的動能。

全系統核對：

```text
H(t) - H(0) = 外部供能 + 阻尼能量變化 + 彈性衝量浮點誤差 + 殘差
P(t) - P(0) = 外部帶入動量 + 阻尼衝量 + 重力衝量 + 地形反作用衝量 + 殘差
```

另核對目標自己的能量：直接擾動供能、阻尼、二體轉移與地形反射浮點誤差。重力做功另記 `W_g=g*(z_before-z_after)`；它與位能變化互相對應，不能在 `K+g*z` 帳本內再加一次。固定地形的理想反射不做淨功，但可以把垂直與水平動能重新分配。

73 次發球全部在規劃時刻接觸；保留後續互動後，共發生 348 次二體碰撞。壞谷的 25 次發球，初次接觸送入目標的動能增量中位數約 **0.1274**，範圍 **0.1049–0.1615**；新球初始位能中位數約 **0.0474**。每次碰後目標總能量都高於障壁，但仍沒有越障。總能量超過障壁只是必要條件，尚需合適的運動方向與保留足夠能量的後續軌跡。

目前發球讓兩球在接觸時具有相同高度、垂直速度及切向速度，只有水平法向分量不同。等質量彈性碰撞會交換該法向分量；因此首次碰撞可表達為對目標施加一個特定速度衝量。後續多球互動才可能提供超出單次衝量的行為，本輪沒有證據顯示這些互動帶來優化優勢。

實際供能也有差異：隨機與方向配對組每例都是 20 球次等價擾動，平均 0.20；小球在壞谷／好谷／二次函數分別發了 25／24／24 球，平均供能 0.25／0.24／0.24。在共同 1,500 次呼叫內，三種介入的每條軌跡實際都供能 0.20。這輪匹配供能上限，不是固定時間下逐條匹配實際支出，更不是匹配目標最後獲得的動能。

壞谷的固定時間 oracle 呼叫中位數為繼續運動 **1,613**、隨機擾動 **1,633**、方向配對 **1,638**、小球 **3,302**。共同 1,500 次上限下，中位物理時間分別為 **23.25、23.05、22.95、12.25**。小球另需中位 529 次粒子對預測，因此計算代價需要單獨評估。

## 驗證與限制

- 全部 240 條完成時間 25，無接觸／數值失敗，無預算提早停止。
- 全系統能量帳本最大殘差 `2.55e-15`；目標能量帳本 `1.45e-15`；動量帳本 `3.08e-15`。
- 從事件前後速度重新計算，二體動能／動量最大誤差分別為 `9.71e-17`／`1.11e-16`。
- 獨立核對了 60 組共用初態、首次方向與時間配對、供能上限、輔助球不刪除、二體轉移帳本與重力做功。保存的模擬程式雜湊全部相符。
- 完整測試 **128 passed**，涵蓋停滯誤觸、精確供能、真實接觸、開放系統帳本、只評分原目標，以及已提交介入後的預算失敗。

預檢另外發現：幾乎靜止時，地形多項式極小的高次係數會讓碰撞求根失準。本輪在有界誤差內裁去求根用的微小高次尾項，仍用原多項式驗證接觸，並新增近靜止長時間反彈的回歸測試；沒有用速度縮放或補充能量修正。

本輪仍只支援孤立的空中二體衝量與獨立地形反彈。群體持續接觸、共享多點接觸、一般黑箱神經網路接觸定位尚未完成。新增質量的供能預算依賴位能參考，對 loss 的垂直平移敏感；未來需要明確的發球器／儲能槽模型與尺度處理。

## 對 proposal 的含意

可以保留「停滯時以有限外部供能改變動量」作研究假設，但目前不能寫成碰撞能改善優化的已驗證結論。這輪最清楚的兩個問題是：**停滯判準沒有辨識是否值得介入；當介入有用時，小球仍需證明比直接衝量值得其額外成本。**

下一版應先研究如何避免干擾已接近好解的軌跡，並以廉價隨機衝量作必要基線。若繼續研究小球，還需加入實際目標獲能或實際衝量匹配的控制，分離首次能量轉移與後續多球互動。這些屬於下一輪假設，本輪沒有按結果調參重跑。

## 重現與原始資料

```sh
python3 run_strategic.py --output output/strategic_new --seeds 20 --steps 500
python3 -m pytest -q
```

輸出禁止覆寫已有 `config.json` 的資料夾。`output/strategic/config.json` 保存設定、環境與模擬程式雜湊；`runs`、`aggregate`、`paired` 分別保存每次執行、彙總與對基線配對比較。`trajectories/`、`events/`、`interventions/`、`detectors/` 保留逐步紀錄。`audit.json`、`launch_transfers.csv`、`terminal_scores.csv` 是從原始紀錄另外核對及衍生的診斷，不改動主實驗。
